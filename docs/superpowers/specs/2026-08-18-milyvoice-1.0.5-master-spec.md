# MilyVoiceTraductor 1.0.5 — Especificación maestra

## Propósito

MilyVoiceTraductor debe ser una aplicación Windows local, ligera y usable sin GPU para escuchar audio, transcribirlo, traducirlo al español y presentar la traducción como subtítulos y, opcionalmente, como voz sintetizada en tiempo real. Debe cubrir reuniones, pestañas web, videos, clases, cursos, canciones, micrófono, audio del sistema y archivos multimedia compatibles.

La base funcional validada es el commit de código `6f5cd6242472ce0ff760632e18c917a9d844642e` de `pruebas`, donde ya funcionaron subtítulos sobre Google Meet, runtime Python privado, pack `realtime-m2m100`, extensión Chromium, Native Messaging, GUI Windows sin consola, NSIS e instalación real. Los commits posteriores de documentación no alteran esa base ejecutable.

## Requisitos consolidados solicitados

### 1. Aplicación y privacidad

- Windows x64 como plataforma principal de entrega.
- Tauri/Rust para el Desktop y Svelte para la interfaz.
- Runtime Python privado incluido por la aplicación; el usuario no instala Python, `winget`, entornos virtuales ni dependencias manualmente.
- Procesamiento local por defecto. Audio, transcripción, traducción, diarización, sesiones y TTS no se envían a servicios cloud.
- Los modelos se descargan después de abrir la aplicación, no se incrustan como pesos gigantes dentro del NSIS.
- Las descargas de modelos se realizan desde repositorios fijados por revisión/hash y se verifican antes de activarse.
- No mostrar consolas negras ni procesos auxiliares visibles. El ejecutable Desktop debe conservar `IMAGE_SUBSYSTEM_WINDOWS_GUI` y los procesos Python auxiliares deben ejecutarse sin ventana.
- Logs locales con redacción de secretos y sin almacenar audio/transcripciones salvo consentimiento explícito.
- La versión visible, Tauri, Cargo, Node, motor, workflows, instalador, release y artefactos deben coincidir en `1.0.5`.

### 2. Pack de IA principal

El pack comercial/default sigue siendo:

- ASR: `Systran/faster-whisper-small` fijado por commit.
- Traducción: `facebook/m2m100_418M` fijado por commit y convertido localmente a CTranslate2 INT8.
- Destino principal: español.
- Origen automático con prioridad funcional a inglés y chino.
- CPU INT8 como ruta obligatoria; CUDA opcional si existe.

No se sustituirá este pack antes de medir y aplicar la optimización CPU descrita en el plan específico.

### 3. Traducción de reuniones

- Google Meet, Microsoft Teams Web y Zoom Web deben seguir funcionando.
- Capturar el audio reproducido por la pestaña sin silenciar la reunión al usuario.
- Mostrar subtítulos superpuestos sobre la reunión.
- Mostrar texto original y traducción al español.
- El usuario puede ocultar el original.
- La sesión debe indicar estados reales: `Capturando`, `Audio detectado`, `Silencio`, `Transcribiendo`, `Traduciendo`, `Hablando`, `Fuente perdida`.

### 4. Cualquier pestaña con audio/video

- La extensión no debe limitarse a tres dominios de reunión.
- Debe funcionar en pestañas `http/https` capturables por Chromium: YouTube, Vimeo, cursos, capacitaciones, reproductores HTML5, radio web y sitios equivalentes.
- Páginas protegidas del navegador (`chrome://`, Web Store y equivalentes) se excluyen con mensaje claro.
- El overlay debe inyectarse dinámicamente y ser independiente del DOM específico del sitio mediante Shadow DOM.

### 5. Audio del sistema y micrófono

Fuentes soportadas:

- `browser_tab`: audio de la pestaña activa.
- `system_loopback`: audio reproducido por Windows.
- `microphone`: dispositivo de entrada elegido.
- `media_file`: audio procedente del reproductor interno.

Si una sesión está activa pero no llegan muestras útiles:

- medir RMS/peak;
- mostrar `No se detecta audio`;
- permitir cambiar de fuente;
- para navegador, ofrecer fallback a audio del sistema.

### 6. Transcripción y subtítulos en tiempo real

- La transcripción original debe poder aparecer antes que la traducción final.
- Eventos parciales y finales deben ser distintos.
- El texto parcial no debe disparar traducciones redundantes continuamente.
- El texto estable se traduce y se emite como subtítulo final.
- La cola nunca puede crecer indefinidamente cuando el hablante va más rápido que la CPU.
- La UI debe mostrar latencia y estado de cola localmente.

### 7. Rendimiento CPU

- Funcionar de forma útil sin GPU es requisito principal.
- Detectar capacidad de CPU y repartir threads explícitamente entre ASR y traducción.
- No depender de defaults estáticos de CTranslate2/Faster-Whisper.
- Evitar sobresuscripción de núcleos.
- Usar VAD/energy gate para no ejecutar Whisper durante silencio claro.
- Usar ring buffer y ventanas adaptativas en conversación.
- Ejecutar ASR y traducción como etapas desacopladas con colas limitadas.
- Mantener métricas locales: `audioQueueMs`, `asrMs`, `translationMs`, `ttsQueueMs`, `realTimeFactor`, perfil CPU y fragmentos pendientes.
- Si la máquina no sostiene el ritmo, reducir frecuencia de parciales/word timestamps antes de permitir atraso acumulativo.

### 8. Voz española en tiempo real

Modos de salida:

- `Subtítulos`.
- `Subtítulos + voz`.
- `Solo voz`.

Requisitos:

- TTS local y opcional.
- Primera implementación usando voces instaladas de Windows para no añadir otro modelo grande al paquete base.
- Cola TTS independiente para no bloquear ASR/traducción.
- Ducking opcional del audio original durante la voz española.
- Protección anti-feedback para que MilyVoice no transcriba su propia voz sintetizada.
- No abrir consola al sintetizar.

### 9. Múltiples hablantes

- Detectar `Hablante A`, `Hablante B`, `Hablante C`, etc. mediante embeddings/clustering local cuando el usuario active identificación de hablantes.
- Mantener `speakerId` estable durante la sesión.
- Asignar un color estable a cada speaker.
- Permitir renombrar speakers.
- Modos: `todas`, `dominante`, `fijado`.
- En modo `dominante`, priorizar continuidad acústica del hablante principal.
- En modo `fijado`, ignorar otros hablantes para transcripción/traducción salvo cambio manual.
- El usuario puede asignar a cada speaker una voz TTS masculina, femenina o neutra.
- No inferir automáticamente género, identidad, edad u otros atributos personales a partir de la voz.

### 10. Video y audio local

- Vista Desktop `Aprender con video/audio`.
- Abrir archivos compatibles con WebView2/Windows, por ejemplo MP4, WebM, MP3, WAV y M4A cuando exista codec disponible.
- Reproductor integrado con play/pause/seek/volumen.
- Traducir mientras reproduce.
- Pintar subtítulos encima del video dentro de la misma aplicación.
- Para formatos no soportados, error explícito; FFmpeg no se bundleará todavía.

### 11. Canciones y aprendizaje de inglés

Modo educativo/karaoke:

- Español como línea principal de comprensión.
- Inglés original debajo para aprendizaje.
- Modo karaoke resalta palabra o fragmento inglés según el momento de audio.
- `word_timestamps` solo se activa cuando el modo lo necesita.
- En CPU débil, degradar automáticamente de resaltado por palabra a resaltado por frase.
- `music_mode` usa ventanas/contexto distintos de conversación y VAD menos agresivo para no cortar letras por música continua.
- El objetivo es enseñanza/comprensión; la precisión depende de la separación entre voz, instrumentos y mezcla original.

### 12. Temas y vistas

Vistas:

- `Reunión`.
- `Educativo`.
- `Karaoke`.
- `Compacto`.

Temas mínimos:

- `Mily azul`.
- `Oscuro cine`.
- `Clase clara`.
- `Alto contraste`.
- `Karaoke neón`.

Personalización:

- posición arriba/centro inferior/abajo;
- tamaño;
- opacidad;
- mostrar/ocultar original;
- colores de speaker compatibles con contraste del tema.

### 13. Sesiones y exportación

Persistencia desactivada por defecto.

Cuando el usuario la habilite:

- guardar original, español, timestamps, `speakerId` y palabras opcionales;
- TXT bilingüe;
- SRT español;
- SRT bilingüe;
- VTT bilingüe;
- VTT con cues/spans de palabra cuando exista información karaoke.

### 14. Protocolo local

Mantener compatibilidad con protocolo existente y añadir eventos:

- `audio.level`;
- `transcription.partial`;
- `transcription.final`;
- `translation.final`;
- `speaker.changed`;
- `tts.started`;
- `tts.finished`;
- `pipeline.metrics`.

El canal de audio podrá negociar PCM binario por WebSocket para evitar Base64/JSON en cada bloque, conservando fallback compatible durante la transición.

### 15. Criterios de aceptación

No se marca una candidata como terminada si no supera:

- pruebas Python;
- typecheck/tests/build frontend;
- Rust tests Linux/Windows;
- Clippy `-D warnings`;
- privacidad y source guards;
- prueba de versión 1.0.5;
- prueba de subsistema Windows GUI;
- bootstrap/runtime privado;
- Native Messaging;
- audio real → transcripción → traducción → subtítulo;
- prueba de habla inglesa rápida sin crecimiento monotónico de cola;
- captura de pestaña genérica;
- captura loopback Windows;
- micrófono;
- archivo multimedia;
- speakers/colores/foco;
- TTS y anti-feedback;
- modo educativo/karaoke;
- exportación SRT/VTT;
- NSIS generado e instalado realmente;
- ZIP extensión y SHA-256.

Solo después se fusiona a `main`, se repite CI de `main` incluyendo prueba real del pack y se publica el instalador final.

## Restricciones de esta iteración

- No clonación de voz.
- No inferencia automática de género/edad/identidad.
- No cloud obligatorio.
- No cambio de destino principal fuera de español.
- No FFmpeg embebido todavía.
- No reemplazar Whisper Small/M2M100 por otro stack antes de completar benchmarking y optimización del pipeline actual.
