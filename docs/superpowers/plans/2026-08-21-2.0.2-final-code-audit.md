# MilyVoiceTraductor 2.0.2 — auditoría final código por código

**Objetivo:** cerrar el hotfix estable con evidencia de comportamiento, no solo compilación.

## Contratos que no pueden romperse

1. El instalador prepara runtime, motor, bridge y extensión; no descarga modelos.
2. Un modelo ausente no bloquea la app; un runtime/bridge roto sí entra a reparación.
3. Primer arranque limpio abre Desktop y no crea `current.json` ni muta modelos.
4. Un bootstrap roto hace fallar NSIS; nunca hay falso `Installation Complete`.
5. Las operaciones de Model Manager no pueden competir entre sí.
6. Un pack instalado pero corrupto debe poder repararse/redescargarse desde `Instalar`.
7. Runtime/bridge/modelos conservan integridad y errores públicos sanitizados.
8. El build de release debe reducir deriva de toolchain/dependencias.
9. Frontend, Python, Rust/Clippy, MegaBench, Windows GUI, NSIS, instalación y reinstalación deben pasar en un mismo SHA final.

## Ciclos TDD

### A. Onboarding / bridge
- RED: bridge ausente debe requerir onboarding/reparación.
- GREEN: `needsOnboarding` y `Onboarding.svelte` exigen runtime + bridge, pero nunca modelo/extensión.

### B. Recuperación de modelo corrupto
- RED: instalar → corromper → reinstalar debe recuperar el pack.
- GREEN: cuarentena/reemplazo transaccional del pack inválido y nueva verificación.

### C. Exclusión mutua de Model Manager
- RED: contrato/UI exige una sola mutación a la vez.
- GREEN: bloqueo backend compartido + botones globalmente deshabilitados durante operación.

### D. Estado/error de Model Manager
- RED: una operación posterior no debe heredar un error anterior.
- GREEN: limpiar error al iniciar cada operación y mostrar fallo de carga/verify explícitamente.

### E. Reproducibilidad del release
- Verificar ausencia/presencia de `Cargo.lock`.
- Fijar toolchain Rust del release.
- Congelar dependencias Python usadas por runtime o registrar/validar resolución exacta.
- Mantener SHA del runtime Python y VC++ app-local.

### F. Diagnóstico / calidad
- Corregir textos 2.0.1 obsoletos en tests 2.0.2.
- Resolver warnings del build que oculten deuda real, sin desactivar controles globales.

## MegaGate final

Un solo SHA debe pasar:

`Source/Privacy → AI tests/stress → Frontend typecheck/tests/build → Rust fmt/tests/Clippy → runtime privado → imports → Native Messaging → MegaBench EN/ZH→ES → Desktop → WINDOWS_GUI → NSIS → bootstrap negativo → first-run sin modelos → instalación/reinstalación → extensión → SHA256 → artifact`.

No se promociona `v2.0.2` hasta completar este gate y verificar el release público.
